## What is the difference between `joblib` and `pickle`?

Both `joblib` and `pickle` are Python serialisation libraries that convert Python objects into byte streams for storage and later reloading. However they differ in important ways:

### pickle
- Python's built-in serialisation module — no installation required
- General-purpose: can serialise almost any Python object
- Stores data as a single byte stream
- Slower for large NumPy arrays and scikit-learn models
- No built-in compression

### joblib
- Part of the scikit-learn ecosystem, specifically designed for scientific Python objects
- Significantly faster for large NumPy arrays — uses memory-mapped files and efficient array serialisation
- Built-in compression support (`compress=1` to `compress=9`)
- Preferred by scikit-learn's own documentation for saving fitted models
- Can save large arrays as separate `.npy` files internally, improving efficiency

### Key difference in practice:
A Random Forest with 100 trees contains many large NumPy arrays (feature thresholds, leaf values). `joblib` serialises these arrays far more efficiently than `pickle` — both in speed and file size.

## Which one did I use, and why?

I used **`joblib`** for both the ensemble model and the lightweight HGB model.

```python
import joblib

# Save
joblib.dump(calibrated, 'icu_mortality_model.pkl')
joblib.dump(best_threshold, 'icu_mortality_threshold.pkl')

# Load
model = joblib.load('icu_mortality_model.pkl')
threshold = joblib.load('icu_mortality_threshold.pkl')
```

**Reasons:**
1. The ensemble model (HGB + RF + XGBoost) contains large NumPy arrays internally. `joblib` serialises these efficiently.
2. scikit-learn's official documentation recommends `joblib` for saving fitted estimators.
3. The `CalibratedClassifierCV` wrapping the `VotingClassifier` is a complex nested object — `joblib` handles this reliably.
4. For the lightweight model, I used `compress=3` to reduce file size while keeping load times reasonable.

## Was my model reproducible in a different notebook? What did I need to do to make that work?

### Initial Challenge
When the model was trained in `4_Data_Modeling.ipynb` and loaded in `6_Voila_Dashboard.ipynb`, several issues arose:

**Issue 1 — scikit-learn version dependency**  
`joblib` serialises the model with metadata about the scikit-learn version used during training. Loading in a different environment with a different scikit-learn version can produce warnings or errors. I resolved this by pinning exact dependency versions in `requirements.txt`.

**Issue 2 — File path differences**  
The model was trained and saved in the project root directory. The dashboard loaded it using a relative path `'icu_mortality_model_light.pkl'`. This worked correctly as long as Voilà was launched from the same directory.

**Issue 3 — Model size for deployment**  
The full ensemble model (361MB) caused memory issues on the deployment server (LATTE). The server ran out of RAM when loading the model. I solved this by extracting just the HGB component and recalibrating it independently:

```python
# Extract HGB pipeline from ensemble
hgb_pipeline = best_hgb  # already a full Pipeline with preprocessor + SMOTE + HGB

# Recalibrate independently
hgb_calibrated = CalibratedClassifierCV(hgb_pipeline, method='sigmoid', cv='prefit')
hgb_calibrated.fit(X_cal, y_cal)

# Save lightweight model
joblib.dump(hgb_calibrated, 'icu_mortality_model_light.pkl', compress=3)
```

This reduced the model from 361MB to under 100MB and RAM usage from 6GB+ to under 1GB.

**Issue 4 — Git LFS incompatibility**  
The deployment server did not support Git LFS. Even though the model was tracked by Git LFS, the server downloaded only the LFS pointer file (134 bytes) instead of the actual model. The dashboard would silently fall back to demo mode.

I resolved this by:
1. Removing the model from Git LFS tracking: `git lfs untrack "*.pkl"`
2. Committing the lightweight model directly as a regular file (under GitHub's 100MB limit)
3. The large ensemble model was added to `.gitignore` and kept only on the HPC

**Issue 5 — Missing `dashboard_summary.json` for deployment without raw data**  
The MIMIC-IV dataset cannot be shared publicly due to the PhysioNet data use agreement. Without it, the Overview and Data Explorer tabs would show "Reference dataset not found."

I pre-computed aggregated summary statistics (no individual patient records) and committed `dashboard_summary.json` to the repository. The dashboard loads this JSON as a fallback when the CSV is not present.

### Steps required for full reproducibility:
1. Clone the repository
2. Create a Python 3.10 conda environment
3. Install exact dependency versions from `requirements.txt`
4. Run `jupyter trust 6_Voila_Dashboard.ipynb`
5. Launch with `voila 6_Voila_Dashboard.ipynb --config=voila_config.py`

The `voila_config.py` disables XSRF protection required for the deployment server's reverse proxy, and sets the correct base URL for the LATTE deployment environment.
